# 無障礙內容產生器（ck-a11y-generator）

將公告、活動、招生等常見公版內容，透過拖拉區塊的方式編排，並產出符合 **WCAG 2.1 AA／AAA** 的語義化 HTML 原始碼，供貼入 CKEditor 等後台文章編輯器使用。

線上網址：https://huaiyingwang.github.io/ck-a11y-generator/

---

## 一、專案定位

- 使用對象：學校、政府機關、法人／協會等單位的網站編輯人員，非工程背景。
- 核心目的：讓不懂 HTML 的使用者也能產出「無障礙合規」的內容原始碼，避免人工手刻標籤時漏掉 alt、標題跳階、對比度不足等問題。
- 交付形式：**純靜態網頁（`index.html`＋`style.css`＋`main.js`）**，無需建置流程、伺服器與資料庫，可直接用 GitHub Pages 發布。

---

## 二、技術架構

| 項目 | 說明 |
|---|---|
| 框架 | Vanilla JS（無框架），Bootstrap 5（CDN） |
| Word 匯入 | [mammoth.js](https://github.com/mongodb/mammoth.js)（CDN），**在瀏覽器端本機解析 .docx**，檔案不會上傳到任何伺服器 |
| 資料儲存 | 無資料庫、無 localStorage。「存草稿／讀草稿」是下載／上傳 JSON 檔到使用者自己的電腦 |
| 後端 / API | **無**。所有邏輯（HTML 產生、無障礙檢測、對比度計算）皆為純前端 JS 規則運算，非 AI 判斷 |
| 部署 | GitHub Pages（`master` branch / root） |

> 目前架構刻意不依賴任何後端與第三方 API，優點是可離線使用、無資安／隱私疑慮（內容不會外流到伺服器），也不會有 API 費用或額度限制。

### 檔案結構

```
ck-a11y-generator/
├── index.html   ← 只放 HTML 結構（工具列、面板、對話框），不含 <style> 與 inline script
├── style.css    ← 工具介面樣式（載入順序在 Bootstrap 之後，才能覆寫）
├── main.js      ← 全部程式邏輯：資料模型、HTML 產生、無障礙檢測、範本庫、Word 匯入、草稿存讀
└── README.md
```

- `main.js` 以 IIFE 包住，不會產生全域變數；在 `index.html` 中放在 Bootstrap 與 mammoth 的 CDN `<script>` 之後、`</body>` 之前，順序不可調換
- 輸出給後台的原始碼（內嵌樣式、類別模式的 `<style>` 區塊、螢幕閱讀器隱藏文字）由 `main.js` 動態產生，屬於輸出內容，與介面樣式 `style.css` 無關

## 三、功能規格

### 3.1 內容區塊（可拖拉排列、複製、刪除）

標題、段落、清單、圖片、圖文並排、表格、按鈕連結、檔案下載、提示方塊、常見問答（FAQ）、引言、影音（YouTube / Vimeo 內嵌）、分隔線。

### 3.2 常用版型與範本庫

- **常用版型**（左側下拉清單）：依單位類型分類：通用／學校／政府機關／法人協會，各自內建「最新消息」「招生公告」「招標公告」「捐款資訊」等常見版型，點一下直接加到畫布。
- **範本庫**（左側「瀏覽範本庫」按鈕）：共 67 套整頁範本（含上述 17 套常用版型），可依「單位類型」×「內容主題」（公告／招生報名／報導／介紹／表格／其他）篩選。
  - 卡片縮圖與畫布共用 `previewHTML()`，並列出使用的區塊種類與即時檢測結果（依目前 AA／AAA 等級）
  - 圖片、檔案、連結的網址與圖片替代文字要放入實際素材才能填，另計為「素材待填」，不算檢測失敗
  - 「加到版面」接在現有內容後面；「取代全部」在畫布有內容時會先在卡片上確認，可選「先存草稿再取代」（本工具沒有復原功能）
- **我的範本**：可把目前畫布存成自訂範本，會一起寫進「存草稿」下載的 `draft.json`（`my` 欄位，草稿格式 `v:2`，仍可讀舊版 `v:1`）。沒存草稿就關閉網頁，自訂範本會消失。

### 3.3 Word 匯入

- 支援貼上內容（Ctrl+V）或上傳 `.docx` 檔
- 自動保留標題、段落、清單、表格結構，清除 Word 多餘格式
- 圖片需另外上傳到後台媒體庫，再回填網址

### 3.4 即時無障礙檢測（`audit()`）

依 WCAG 2.1 AA／AAA 規則即時掃描，涵蓋：

- 標題階層是否跳階（H2 → H4 等）
- 圖片是否缺少 `alt`、`alt` 是否為檔名或贅字
- 連結文字是否為「這裡」「更多」等無意義字詞
- 相同文字連結是否指向不同網址
- 表格是否有 `<caption>`、`<th scope>`
- 按鈕底色與白字對比是否達 4.5:1（AA）／7:1（AAA）
- 另開新視窗連結是否標註提示文字
- 影音是否有 `title` 與逐字稿（AAA 必填）

檢測結果會即時顯示分數與「符合 / 尚有 N 項須修正」，並可點擊項目跳轉到對應區塊。

### 3.5 原始碼輸出

三種輸出模式：

| 模式 | 說明 |
|---|---|
| 純語義（建議） | 只有標籤，樣式完全交給後台網站的既有 CSS |
| 內嵌樣式 | 每個標籤自帶 `style`，外觀最穩定，不受後台樣式影響 |
| 類別＋樣式表 | 產生專屬前綴 class（避免污染既有樣式）＋對應 CSS 區塊 |

支援複製到剪貼簿、下載 `.html` 檔。

## 四、無障礙規範對照（依 CLAUDE.md 全域規範落實）

- 所有互動元素皆可鍵盤操作，`:focus-visible` 有明顯樣式，未使用 `outline:none` 移除焦點框
- 圖片統一走 `<img alt="">`／裝飾圖 `alt=""`
- 表單皆有 `label` 對應 `for`／`id`
- 連結文字檢核禁止「點這裡」等模糊字詞
- `prefers-reduced-motion` 已處理（關閉所有 transition／animation）
- `<html lang="zh-Hant-TW">`

## 五、部署方式

```bash
git add index.html style.css main.js
git commit -m "更新內容"
git push
```

Push 後 GitHub Pages 會在 1–2 分鐘內自動重新部署，網址不變。

> `index.html`、`style.css`、`main.js` 三個檔案必須一起部署。少了 `style.css` 畫面會沒有樣式；少了 `main.js` 所有功能都無法運作。

## 六、未來可選擴充（皆需額外串接 API／後端，目前尚未實作）

以下為對話討論過、但**刻意先不做**的加強方向，之後有需求再評估：

| 需求 | 需要的技術 | 備註 |
|---|---|---|
| AI 自動生成圖片 alt 文字 | 影像辨識 / LLM API（如 Claude API） | 上傳圖片 → 回傳描述文字，可大幅降低編輯人員撰寫 alt 的門檻 |
| 雲端草稿同步（跨裝置） | Firebase / Supabase 等後端服務 | 取代目前的「下載／上傳 JSON」方式 |
| 連結有效性自動檢查 | 需一個小型後端代理（前端受 CORS 限制無法直接打任意網址） | 定期掃描已填入的連結是否失效 |
| 多人協同編輯 | WebSocket + 後端 | 目前為單機單使用者操作 |
| PWA 離線安裝 | `manifest.json` + Service Worker | 因工具本身已可離線運作，加上此設定可讓使用者「安裝」成 App |
